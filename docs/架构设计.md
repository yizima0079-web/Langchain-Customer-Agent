# AI 智能客服微信小程序商城系统 —— 架构设计

## 1. 项目定位

本项目是一个“微信小程序商城 + AI 智能客服 + Web 管理后台”一体化系统，当前代码由三个独立运行单元组成：

| 单元 | 目录 | 技术 | 主要职责 |
|---|---|---|---|
| API 服务 | `server/` | Python、FastAPI、SQLAlchemy、LangChain | 认证、商品交易、文件处理、RAG 客服、统计接口 |
| 管理后台 | `client/` | Vue 3、Vite、Element Plus、Pinia、ECharts | 管理员登录、运营管理、知识库管理、数据看板、客服调试 |
| 用户端小程序 | `weixin/` | 微信原生小程序 | 商品浏览、购物车、下单、地址、支付方式、订单、AI 客服 |

系统核心链路：

1. 管理员上传知识库文件。
2. 后端解析文件并按固定窗口切分文本。
3. 文本通过 DashScope 兼容接口生成向量，持久化到 Chroma。
4. 用户提问时检索相关文本块，拼接系统提示词后调用 Qwen 聊天模型生成答案。
5. Web 后台使用同步接口调试客服；微信小程序优先使用流式接口逐段显示答案。

## 2. 技术栈与运行依赖

| 层次 | 当前实现 |
|---|---|
| Web 前端 | Vue 3、Vite、Vue Router、Pinia、Element Plus、Axios、ECharts |
| 小程序 | 微信原生小程序、WXML、WXSS、JavaScript、自定义 TabBar |
| 后端 | Python、FastAPI、Uvicorn、Pydantic |
| 数据访问 | SQLAlchemy 2.x、PyMySQL |
| 关系数据库 | MySQL 8，默认端口 3306，数据库名 `shop_agent` |
| 认证 | JWT；密码按当前项目约定使用 MD5 摘要存储 |
| 大模型 | LangChain、`langchain-openai`、OpenAI 兼容协议 |
| 聊天模型 | 配置项 `LLM_MODEL`，默认 `qwen3.8-flash` |
| 嵌入模型 | 配置项 `EMBEDDING_MODEL`，默认 `qwen3.7-text-embedding-flash` |
| 向量存储 | Chroma，集合名 `knowledge_base` |
| 文档解析 | `langchain-community`、`pypdf`、`python-docx`、`langchain-text-splitters` |
| 文件存储 | 配置项 `UPLOAD_DIR`，默认 `F:/uploads14` |

模型服务配置通过 `server/.env` 管理：`OPENAI_API_BASE` 为 OpenAI 兼容接口地址，`OPENAL_APLKEY` 为当前项目使用的密钥变量名，`OPENAI_API_KEY` 是兼容回退变量；`CHROMA_DIR` 默认值为 `F:/uploads14/chroma`，`API_PREFIX` 默认值为 `/api/v1`。

### 4.2 认证与权限

- 登录成功后签发 JWT，客户端通过 `Authorization: Bearer <token>` 携带。
- 普通用户和管理员通过 `User.role` 区分：`0=普通用户`、`1=管理员`。
- 管理后台路由由前端登录守卫拦截；后端管理接口使用 `get_current_admin` 再次校验。
- 商品、分类、轮播图、用户、知识库和统计接口的管理操作需要管理员权限。
- 购物车、订单、地址等用户业务接口需要登录。
- `/chat`、`/chat/stream` 支持游客访问，通过 `session_id` 区分会话。

## 5. 数据库设计

数据库初始化脚本位于 `server/sql/`，字符集为 `utf8mb4`。

| 表 | 作用 | 关键字段 |
|---|---|---|
| `user` | 用户与管理员 | `username`、`password`、`role`、`status` |
| `category` | 商品分类 | `name`、`sort`、`status` |
| `product` | 商品主数据 | `category_id`、`price`、`original_price`、`stock`、`sales`、`cover_image`、`images`、`status` |
| `banner` | 首页轮播图 | `title`、`image`、`sort`、`status` |
| `address` | 用户收货地址 | `user_id`、`name`、`phone`、省市区、`detail`、`is_default` |
| `cart` | 用户购物车 | `user_id`、`product_id`、`quantity`；用户与商品组合唯一 |
| `order` | 订单主表 | `order_no`、`user_id`、`total_amount`、`status`、`address_id`、`remark` |
| `order_item` | 订单明细快照 | `order_id`、商品 ID、商品名称、商品图片、成交价、数量 |
| `knowledge_file` | 知识库文件记录 | `filename`、`file_type`、`file_path`、`status`、`chunk_count`、`error_msg` |
| `chat_message` | AI 客服消息 | `session_id`、`role`、`content`、`created_at` |

订单状态：

```text
0 待付款 → 1 待发货 → 2 待收货 → 3 已完成
       ↘ 4 已取消
```

当前下单实现会：校验地址属于当前用户；支持立即购买或购物车结算；创建订单和订单明细并保存商品快照；扣减库存、增加销量，购物车结算后清空购物车；普通用户只能取消自己的待付款订单，取消时恢复库存和销量。

项目当前没有独立的支付订单表或第三方支付回调，支付页是支付方式选择和订单状态推进页面。

## 6. AI 客服与知识库

### 6.1 知识库入库

```text
管理员上传文件
      │
      ▼
校验扩展名并使用 UUID 文件名落盘
      │
      ▼
knowledge_file.status = 0（待处理）
      │
      ▼
TextLoader / PyPDFLoader / Docx2txtLoader 解析
      │
      ▼
RecursiveCharacterTextSplitter
chunk_size = 500，chunk_overlap = 50
      │
      ▼
DashScopeEmbeddings 生成 1024 维向量
      │
      ▼
写入 Chroma knowledge_base 集合
      │
      ▼
成功 status = 1；异常 status = 2 并记录 error_msg
```

支持扩展名：`txt`、`md`、`markdown`、`pdf`、`doc`、`docx`。`.doc/.docx` 当前统一使用 `Docx2txtLoader`，实际二进制 `.doc` 文件是否可解析取决于文件格式兼容性。删除知识库文件时，会尝试同时删除 Chroma 中 `file_id` 对应的向量和本地文件，再删除 MySQL 文件记录。

### 6.2 问答链路

```text
用户问题 + session_id
      │
      ▼
向量检索 top_k = 4
      │
      ▼
系统提示词 + 检索上下文 + 用户问题
      │
      ▼
ChatOpenAI + StrOutputParser
      ├── POST /chat：一次性返回 answer 和 sources
      └── POST /chat/stream：SSE 返回 meta/delta/done 分片
      │
      ▼
chat_message 保存用户消息与助手回答
```

客服提示词要求回答基于知识库上下文、使用中文、保持简洁；当前前端聊天页面不展示匹配文本片段。


### 9.2 小程序客服流式兼容

`utils/api.js` 使用 `wx.request` 的 `enableChunked` 和 `onChunkReceived` 接收 SSE 数据，解析 `meta`、`delta`、`done` 事件并逐段更新消息气泡。若基础库或后端流式接口不可用，则回退到 `/chat`，将完整答案分段渲染，避免页面直接显示连接失败。

## 10. 文件与静态资源

- 上传接口将图片保存至 `UPLOAD_DIR/{category}/`，文件名使用 UUID，返回 `/uploads14/{category}/{filename}`。
- FastAPI 将 `UPLOAD_DIR` 挂载为 `/uploads14` 静态目录。
- 知识库文件保存至 `UPLOAD_DIR/knowledge/`。
- Chroma 数据保存至 `CHROMA_DIR`，与 MySQL 文件记录分离。
- Web 前端通过 Axios baseURL `/api/v1` 访问接口；小程序在 `weixin/utils/api.js` 中维护 `BASE_URL` 和静态资源地址。

## 11. 关键设计决策

1. **统一响应结构**：所有业务接口使用 `code/message/data`，由 Web Axios 和小程序请求封装统一解包。
2. **JWT 双端复用**：Web 管理后台和小程序均使用 Bearer Token，游客客服使用独立 `session_id`。
3. **RAG 服务单例化**：聊天模型、嵌入模型和 Chroma 采用模块级缓存，避免重复初始化。
4. **订单商品快照**：订单明细保留成交时名称、图片和价格，避免商品修改影响历史订单。
5. **库存与取消补偿**：创建订单时扣库存和增加销量；取消待付款订单时恢复库存和销量。
6. **地址复用**：地址独立建模，订单只保存 `address_id`，下单时可复用默认地址或新增地址。
7. **管理与用户端分离**：Web 管理后台负责运营和 AI 知识库维护，小程序负责 C 端交易和客服体验。
8. **流式优先、兼容降级**：小程序客服优先走 SSE 流式接口，基础库不支持时回退同步接口并分段渲染。
9. **文件与向量分离**：原始文件、MySQL 元数据和 Chroma 向量分别存储，删除知识库时执行多处清理。

## 12. 启动方式

```powershell
# 初始化 MySQL
mysql -h localhost -P3306 -uroot -p < server/sql/schema.sql
mysql -h localhost -P3306 -uroot -p < server/sql/data.sql

# 启动后端
cd server
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
# 在 .env 中配置 OPENAL_APLKEY 等参数
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 启动 Web 管理后台
cd client
npm install
npm run dev

# 启动微信小程序
# 使用微信开发者工具导入 weixin/，并在 weixin/utils/api.js 配置后端地址
```

默认访问地址：FastAPI 文档 `http://localhost:8000/docs`，Web 管理后台 `http://localhost:5173`，API 前缀 `http://localhost:8000/api/v1`。
